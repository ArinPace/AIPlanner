# Native subscription Chat controls

Native relay version 4 connects the iPhone Chat tab to the existing account-scoped Planner MCP tool catalog through an authenticated backend adapter. It does not call an inference API or use a VM/extension to forward messages. Calendar, Files, notes/folders, tasks, memory, personal instructions, existing Agent schedule settings, histories and authorized Google data use the same tools, schemas, revision checks and planning gates as Agent. Added app settings tools cover week/month duration scaling and task notification preferences. OS authorization and account sign-in still require the user; these tools do not change app source code or grant deployment access.

The model receives current account instructions and a description of the existing review schedule as context, not an instruction to execute a scheduled review. It discovers tools and their actual JSON schemas. Native transport uses plain `PLANNER_TOOL_REQUEST` / `END_PLANNER_TOOL_REQUEST` markers because rendered website code blocks do not reliably retain Markdown fences. A current response UUID is required. Only a single complete request block at the end of a reply is accepted; stale/ambiguous blocks execute nothing. Legacy fenced requests are also recognized. Requests/results stay out of the visible Planner transcript, which saves the original user message and final answer.

`tool_begin` authorizes a two-hour, owner/chat-scoped request. `tool_call` checks it before every call and uses durable receipts: identical IDs replay the result, changed arguments are rejected, and an uncertain started write is never blindly repeated. Completed/cancelled requests cannot execute more tools. `tool_finish` closes a request; Stop also closes future tool execution. Recovery controls can cancel an abandoned request without claiming earlier writes were rolled back. Calendar changes retain Begin Planning, widget-draft and revision safeguards; the Chat Begin Planning button activates planning without starting a VM job.

Browser Use VM tools are excluded. ChatGPT must use its own cloud browser for websites, when available to its account/mode. Fresh native tool conversations select Work if the website offers it. A website approval or private sign-in pauses the reply and exposes Continue in ChatGPT. The existing native portal shows the original website form; Planner does not copy credentials. After the form/approval is gone the portal returns to Planner. Manual Open ChatGPT remains available while work is running. A connection-status peek cannot consume the pending reply. Canonical chat URLs are bound before completion, including sign-in pauses.

The native client must remain open for the tool relay. Existing Agent scheduled execution remains separate. Older version 3 clients retain ordinary text/file forwarding and do not start these tool turns.

## Verification

Backend ownership/active-turn/schema/duplicate-write tests, settings compare-and-swap tests, legacy device-tool regressions, UI tool-loop/private transcript/interaction fixtures, native secure-form detection (without credential extraction), TypeScript and web builds pass. New service-only tables have RLS enabled, no anonymous/authenticated table grants, composite ownership foreign keys and per-chat active-turn uniqueness. Live subscription-controlled app edits and Brightspace authentication are the next acceptance checks; fixture tests do not prove either.
