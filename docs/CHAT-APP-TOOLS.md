# Native subscription Chat controls

Native relay version 4 connects the iPhone Chat tab to the existing account-scoped Planner MCP tool catalog through an authenticated backend adapter. It does not call an inference API or use a VM/extension to forward messages. Calendar, Files, notes/folders, tasks, memory, personal instructions, existing Agent schedule settings, histories and authorized Google data use the same tools, schemas, revision checks and planning gates as Agent. Added app settings tools cover week/month duration scaling and task notification preferences. OS authorization and account sign-in still require the user; these tools do not change app source code or grant deployment access.

The model receives current account instructions and a description of the existing review schedule as context, not an instruction to execute a scheduled review. It discovers tools and their actual JSON schemas. Native transport uses plain `PLANNER_TOOL_REQUEST` / `END_PLANNER_TOOL_REQUEST` markers because rendered website code blocks do not reliably retain Markdown fences. A current response UUID is required. Only a single complete request block at the end of a reply is accepted; stale/ambiguous blocks execute nothing. Legacy fenced requests are also recognized. Requests/results stay out of the visible Planner transcript, which saves the original user message and final answer.

`tool_begin` authorizes a two-hour, owner/chat-scoped request. `tool_call` checks it before every call and uses durable receipts: identical IDs replay the result, changed arguments are rejected, and an uncertain started write is never blindly repeated. Completed/cancelled requests cannot execute more tools. `tool_finish` closes a request; Stop also closes future tool execution. Recovery controls can cancel an abandoned request without claiming earlier writes were rolled back. Calendar changes retain Begin Planning, widget-draft and revision safeguards; the Chat Begin Planning button activates planning without starting a VM job.

Browser Use VM tools are excluded. ChatGPT must use its own cloud browser for websites, when available to its account/mode. Fresh native tool conversations select Work if the website offers it. Native relay version 5 automatically presents a Planner Connect website sheet for website approval/private sign-in. It retains the original secure form and its submit handler in the same authenticated web view; it hides surrounding conversation/sidebar/composer without copying credential values. The actual destination hostname and original card remain visible. The form width and input font fit the phone. Dialog replacements are followed as authentication advances; unsupported surfaces stay masked rather than showing the full ChatGPT page. Cancel restores the original page layout. Chat → Add sites → Connect Brightspace starts the cloud-browser login request. Manual ChatGPT session inspection is separate from website sign-in. After the form/approval is gone the portal returns to Planner. Manual Open ChatGPT remains available while work is running. A connection-status peek cannot consume the pending reply. Canonical chat URLs are bound before completion, including sign-in pauses. Reply identity/content supplements counts because ChatGPT virtualizes older turns: the live sequence observed a new reply with only three rendered messages after a baseline of five. Known rendered JSON language headers are normalized without changing JSON string escaping. Idempotent backend handoffs retry brief network failures; ChatGPT sends and chat creation are never blindly resent.

The native client must remain open for the tool relay. Existing Agent scheduled execution remains separate. Older version 3 clients retain ordinary text/file forwarding and do not start these tool turns.

## Full app control acceptance — November 5, 2026

Native relay version 6 adds `planner_client_control`: account-scoped, schema-validated commands for all seven tabs, calendar date/view, Settings, theme, zoom and fixed/planned filters. Unsaved editors block navigation. Stop/account changes stop subsequent client commands. Backend acknowledgement is explicitly not device execution: actual native/UI results are returned to ChatGPT.

Native commands read Screen Time state, open user authorization/app selection, start/stop sessions, save/remove task rules, adjust location policy and access a configured NextDNS denylist (including pagination). App selections remain opaque Apple tokens; credentials remain in device storage. Mutations require a fresh state fingerprint and durable receipts. Task rules must match real published calendar occurrences. Folder focus windows are synchronized separately from widget task display so folder rules are retained. OS permission approval, app selection and sign-ins remain user actions. NextDNS live acceptance awaits configured credentials. This is defined UI navigation plus Planner tools, not arbitrary JavaScript, source-code editing or control of OS Settings.

Live signed-in ChatGPT tests in project Test visited all seven tabs, opened/closed Settings, changed/restored theme and read native policy. A second real conversation saved rules for a published folder and child, read both back across separate checks, explicitly removed each and verified absence. Independent device receipts confirmed both removals, no remaining test rules, unchanged selection/location policy and no global session. Temporary calendar events were removed and independently checked absent. Native standalone checks also passed session start/stop, replay, changed-argument/owner/stale rejection and location restore; this establishes native configuration, not new proof of target-app shielding on a physical phone.

Authenticated calls through the same relay/MCP adapter verified note/checklist create/edit/read, nested folders, moving, links, Bin restore with stable IDs, protected To-do and Work access with original content preserved, tag edits, nested recurring folders, one-occurrence exclusion and recurring-folder cascade removal. Recurrence expansion independently confirmed the excluded date empty and the next week intact. Disposable Files test items remain recoverable in Bin. Personal coursework, To-do and Work contents were preserved.

Testing found and repaired a native receipt-cache serialization crash, workspace Postgres statement timeouts, synthetic-task rule pruning and folder rule pruning. Changed-note history processing and service-only atomic workspace delta commits preserve revision, history, quota and ownership controls without rewriting every unchanged note. Both migrations were verified in rollback transactions, including protected notes and service-only grants. Thirty-nine relevant server tests passed, alongside React control fixtures, TypeScript/web builds and the iOS 26.5 simulator build. Brightspace secure-card presentation passed; authentication is still pending the user's Duo phone. Keep Planner open for the subscription relay.
