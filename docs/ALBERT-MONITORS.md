# Albert availability monitors

The existing Agent VM runs read-only Albert browser checks between AI tasks. A check creates its own temporary tab in the already signed-in browser, opens a verified class URL, replays bounded search/navigation steps if necessary and reads a unique class row/status cell. The original user browser tabs and credentials are not read or copied. Enrollment, registration, dropping, swapping and credential entry are outside monitor actions.

The Agent configures monitors through `planner_albert_watch_read` and `planner_albert_watch_save`. It must first discover a working class/section deep link and selectors in the actual browser, including a unique class identity in the watched row. `openValues` and `closedValues` match the entire normalized cell text or one explicit status icon; substring guesses, missing identity, ambiguous selectors and sign-in failures return unknown. This can require read-only search steps for PeopleSoft pages that do not preserve a search in their URL. An unverified URL alone is not a live listener.

Polling defaults to five minutes and runs without an AI request or chat message for unchanged, closed or unavailable observations. Enabled monitors keep the existing paired VM available. No additional VM is created. Checks are best-effort between user tasks and private sign-in sessions, not guaranteed real-time push notifications from NYU.

State, leases and the last known valid status persist in server-only Supabase rows. Unknown checks never erase the last valid status or imply an opening. An initially open class or a closed-to-open transition queues one Main Agent alert using a unique monitor/change receipt. Repeated open observations do not create duplicate alerts. When explicitly requested, the Agent verifies current availability and delivers the alert to the existing verified WhatsApp conversation Arnav. Queueing does not prove message delivery; the Agent must verify the actual send. Do not repeatedly resend an uncertain outcome.

A monitor is operational only after `last_checked_at` is populated and `last_error` is null. Read `last_error`, `last_status` and `last_alert_job_id` to distinguish configuration, source access, change detection and delivery. Pause by saving the same ID/version with enabled false; disabling Albert also suspends checks. Existing ordinary review schedules remain separate.

The Codex approval bridge now handles command, file-change and additional network/filesystem permission requests using the installed app-server protocol. These are real user approvals; unsupported permissions are not automatically granted, and turn grants do not silently become session grants. Source code requested by the user belongs in the worker workspace. The built-in Albert monitor needs no agent-created daemon, shell loop or host-service installation.
