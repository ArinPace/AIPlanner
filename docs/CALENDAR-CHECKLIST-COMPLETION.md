# Calendar block completion

Week agenda rows and Day blocks have a right-side Done action when linked to a Work or To-do checklist item. Folder Done marks its linked descendant activity blocks; folders, rests and travel are not extra required work. Each block stores its own completed occurrence. Explicitly linked blocks retain independent IDs/Done controls instead of being auto-merged together. The parent checklist checks only after every required linked one-off block has been completed. This records progress; it does not change event times or invoke the widget's early-finish rescheduling workflow.

Main and Tutor planning instructions require all required blocks to be mapped with `planner_checklist_read` and `planner_link_event_checklist`. The agent must include every required session and both canonical notes where appropriate, preserve stable item IDs when updating notes, and report ambiguous/unmapped work. Matching uses explicit note/item IDs, never similar titles. IDs survive rich-note edits and are hidden from the user. Recurring routines retain individual occurrence progress without permanently completing a repeating checklist.

Source-confirmed submissions and the existing retirement rule for date-bound assessment/preparation rows remain independent automatic completion paths. Checking a manually completed block never reopens an already checked item or claims attendance/submission just from elapsed time. Checked To-do items remain in their original note; Work's existing seven-day cleanup is unchanged.

The authenticated `/api/calendar/checklist-done` endpoint checks the exact occurrence and current account. A server-only optimistic transaction saves event progress, changed checklist notes and applicable To-do task status together, preserving unrelated files, rich formatting and note/calendar histories. Stale revisions, missing/duplicate item IDs and unmapped blocks fail without partially checking items. Repeated Done requests are idempotent. Calendar metadata changes invalidate an older draft rather than silently replacing its newer completion state.

Verification includes multi-block and cross-folder completion, recurring-folder occurrence scope, stale/ambiguous links, renamed item labels, rich formatting, existing source completion, source-key stability and merge protection; desktop/mobile/day UI, invisible IDs and note edit roundtrip; production build; and rollback-only SQL checks of atomic revisions/writes and server-only privileges.
